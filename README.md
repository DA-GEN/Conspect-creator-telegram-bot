# Сonspect_creator_bot

Telegram-бот, который скачивает видео (YouTube, TikTok, Instagram),
расшифровывает аудиодорожку в текст, анализирует несколько кадров видео и
на основе этого делает структурированный конспект. После результата можно
начать чат и задавать вопросы по содержимому. Поддерживает «проекты» — сбор
нескольких видео с последующим одним общим конспектом, где ИИ сам определяет
тему каждого видео и группирует их по темам.

Использует только бесплатные технологии:
- **aiogram 3.x** — асинхронный Telegram-бот
- **yt-dlp + ffmpeg** — скачивание видео, извлечение аудиодорожки и кадров
- **tikwm.com** — запасной способ для TikTok-слайдшоу (постов из нескольких
  фото, `/photo/<id>`), которые yt-dlp скачивать не умеет вообще
- **Groq Cloud API (free tier)**:
  - `whisper-large-v3` — распознавание речи
  - `qwen/qwen3.8-27b` (fallback `qwen/qwen3.6-27b`) — vision-анализ кадров/фото
  - `openai/gpt-oss-20b` (fallback `qwen/qwen3.8-27b`) — конспект и чат

Бот анализирует и звук, и видеоряд вместе: если в аудио только музыка или
бессвязные звуки — конспект строится по картинке; если видеоряд не несёт
полезной информации (случайный фон, говорящая голова и т.п.) — по речи.

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env  # заполнить BOT_TOKEN и GROQ_API_KEY
python bot.py
```

- `BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather)
- `GROQ_API_KEY` — ключ с https://console.groq.com/keys (бесплатный тариф)

> Требуется установленный `ffmpeg` (используется yt-dlp для извлечения
> аудиодорожки в mp3 и для извлечения кадров из видео).

## Как пользоваться

### Одно видео

1. Отправить боту ссылку на видео (YouTube/TikTok/Instagram).
2. Бот сразу скачивает, расшифровывает и присылает файл
   `result_<последние 5 символов ссылки>.md` со структурированным конспектом
   (учитывает и речь, и визуальные детали с кадров/фото) с кнопкой «💬 Начать чат».
3. Нажать «💬 Начать чат», чтобы задавать вопросы по конспекту — бот отвечает
   через Groq. Выйти — `/endchat`.

### Проект — общий конспект по нескольким видео

1. `/newproject` — начать проект.
2. Присылать ссылки на видео: по одной в сообщении или несколько сразу,
   можно вперемешку в разных сообщениях — до `MAX_PROJECT_VIDEOS` (20) штук.
3. `/finishproject` — завершить и получить файл `project_<id>.md`: бот сам
   определяет тему каждого видео, группирует их (все видео одной темы —
   подряд, одним разделом) и присылает один структурированный конспект по
   всем темам с кнопкой «💬 Начать чат». `/cancelproject` — отменить без
   обработки.

Если у ссылки нет видеопотока (например, TikTok-видео без отдельного
видеопотока), бот расшифровывает аудио без визуального анализа. Для
TikTok-постов из нескольких фото (`/photo/<id>`, слайдшоу) — которые yt-dlp
не поддерживает — используется запасной способ через tikwm.com: он отдаёт
сами фото слайдов (все, не только первые несколько — картинки, которых
больше, чем влезает в один запрос к vision-модели, анализируются батчами) и
фоновую музыку (если есть). Это неофициальный сторонний сервис — если он
окажется недоступен, бот сообщит об этом честно.

Для таких слайдшоу результат — только раздел «Визуальное описание» (без
конспект-таблицы, расшифровки и общих выводов): аудио там обычно просто
музыка, а сами слайды и так исчерпывающе описывают содержание.

### Запрос по конкретной теме

Не нужен общий конспект, а нужен точечный ответ по видео?

```
/context напиши список OSINT-инструментов и их возможностей https://...
```

Текст запроса и ссылка — в любом порядке, в одном сообщении. Бот ответит
именно на запрос (в данном примере — только список инструментов), без
конспект-обвязки и лишних разделов.

## Структура

```
bot.py                    # точка входа: создаёт Bot/Dispatcher, запускает polling
app/
├── commands.py             # список команд для меню Telegram по "/"
├── config.py                # переменные окружения, константы моделей/лимитов, промпты
├── logging_setup.py          # логирование: консоль + logs/bot.log с ротацией
├── state.py                   # состояние в памяти: активные чаты/проекты, VideoResult
├── files.py                    # имя и содержимое .md-файла с результатом
├── keyboards.py                 # inline-клавиатуры, регистрация контекста для чата
├── tg_utils.py                   # safe_edit_text, разбиение длинных сообщений
├── downloader.py                  # yt-dlp + tikwm.com-фолбэк, извлечение кадров ffmpeg
├── groq_client.py                  # все вызовы Groq: STT, vision, конспекты, чат
├── video_pipeline.py                # сбор данных по одному видео (общий для всех сценариев)
└── handlers/
    ├── basic.py                      # /start, /help
    ├── chat.py                        # /endchat, чат-режим, кнопка «Начать чат»
    ├── context.py                      # /context — ответ по конкретному запросу
    ├── project.py                       # /newproject, /cancelproject, /finishproject
    └── video.py                         # обработка ссылок, одиночный конспект

Dockerfile, .dockerignore, docker-compose.yml   # контейнеризация
deploy/bot.service                              # systemd-юнит для VPS без Docker
DEPLOY.md                                       # публикация на GitHub + деплой на хостинг
```

- `.env` — секреты (не коммитится)
- `logs/bot.log` — файл логов с ротацией (5 МБ × 3 бэкапа, не коммитится)
- `requirements.txt` — зафиксированные версии зависимостей

Логи пишутся и в консоль, и в `logs/bot.log`; у каждого модуля свой логгер
(`logging.getLogger(__name__)`), поэтому по имени источника в строке лога
видно, из какой части бота она пришла.

## Производительность

Оптимизации, не влияющие на результат (все константы — в `app/config.py`):

- **`max_tokens` на все вызовы Groq LLM** — без явного лимита модель сама
  решает, сколько генерировать, и на free-тарифе это реально ловит 429 по
  output-tokens-per-minute (наблюдали на `qwen/qwen3.6-27b`, лимит 1000/мин).
- **Кэш результата по URL** (`URL_CACHE_TTL_SECONDS`, 30 мин) — повторная
  присылка той же ссылки не гоняет скачивание/Whisper/vision заново.
  Кэшируются только успехи, не ошибки (они могут быть временными).
- **Параллельно**: извлечение кадров ffmpeg (`extract_frames_sync`), скачивание
  фото+музыки TikTok-слайдшоу, видео внутри проекта (`PROJECT_CONCURRENCY`).
- **TTL на `chat_contexts`** (`CHAT_CONTEXT_TTL_SECONDS`, 1 час) — без него
  токены для кнопки «Начать чат» копились бы в памяти вечно.

**Важный нюанс, найденный на практике:** батчи vision-анализа (несколько
запросов на слайды одного видео) **намеренно не распараллелены**
(`VISION_BATCH_CONCURRENCY = 1`). Проверили на реальном слайдшоу — 2
параллельных запроса одновременно упёрлись в общий rate limit Groq и оба
поймали 429, что дало 68с вместо ожидаемого ускорения (вместо этого
получили очередь ретраев). Когда бутылочное горлышко — общая квота, а не
задержка сети, конкурентность вредит. Если апгрейднете тариф Groq (выше
limit) — можно поднять `VISION_BATCH_CONCURRENCY` в конфиге.
